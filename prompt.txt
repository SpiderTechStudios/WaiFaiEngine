You are working on the existing WaiFai Engine API.

I want you to introduce a complete, production-ready **Expense Management module** into the existing API.

IMPORTANT:

* Do NOT create a separate application.
* Do NOT break existing functionality.
* First inspect the existing architecture, database schema, models, authentication, workspace/account structure, routers, subscriptions/platform payments, and existing financial/payment-related modules.
* Reuse the existing architecture and naming conventions wherever appropriate.
* Do not duplicate concepts that already exist.
* Before implementing, understand how users/accounts/workspaces and routers are currently related.
* The implementation must be multi-tenant and ensure one user/account cannot access another user's expenses.

==================================================

1. PURPOSE
   ==================================================

WaiFai users need to record the real expenses associated with operating their Wi-Fi business.

Examples include:

* Monthly WaiFai platform subscription/license
* Internet bundles purchased for a router
* Electricity
* Router purchase
* Access Point purchase
* UPS purchase
* Switch purchase
* Ethernet cables
* Installation costs
* Router maintenance
* AP maintenance
* Repairs
* Transport
* Rent/site costs
* Staff/technician payments
* SIM/data costs
* Replacement equipment
* Other operational expenses

The objective is for the user to know:

1. How much they actually spent.
2. What they spent it on.
3. When they spent it.
4. Who they paid.
5. Which router/site/device the expense belongs to.
6. Which expense category/type it belongs to.
7. How much they spent on each router.
8. How much they spent on operations overall.
9. How much they spent on WaiFai platform-related expenses.
10. How much they spent excluding platform expenses.

==================================================
2. IMPORTANT DISTINCTION: PLATFORM VS BUSINESS EXPENSE
======================================================

The system must distinguish between:

A. PLATFORM EXPENSES

Expenses paid by the user to WaiFai/platform.

Examples:

* WaiFai monthly subscription
* Platform license
* Platform service charges
* Other future platform charges

B. BUSINESS/OPERATIONAL EXPENSES

Expenses incurred by the user while operating their Wi-Fi business.

Examples:

* Electricity
* Internet bundle
* Router purchase
* AP purchase
* UPS
* Switch
* Cables
* Repairs
* Installation
* Transport
* Technician payment
* Site expenses
* Other expenses

The architecture must support filtering:

* All expenses
* Platform expenses only
* Non-platform expenses only
* Expenses for a specific router
* Expenses for a specific expense type
* Expenses within a date range
* Expenses for a specific site/location if supported by the existing architecture

Do NOT hard-code the platform subscription as the only platform expense. The data model should support future platform expense types.

==================================================

================

Expense types/categories must be manageable by the ADMIN.

The admin should be able to create, edit, activate/deactivate expense types.

Examples:

* Platform Subscription

The admin must be able to add new expense types in the future without requiring a code deployment.

Each expense type should have enough information to determine whether it is:

* platform expense
  OR
* business/operational expense.

For example:

expense_type:
name: "Platform Subscription"
category: "platform"

expense_type:
name: "Electricity"
category: "operational"

Use an appropriate enum/string structure consistent with the existing project architecture.

==================================================
4. EXPENSE RECORD
=================

Create a proper expense entity.

At minimum an expense should support:

* id
* account/workspace/user ownership according to the existing architecture
* router_id nullable
* expense_type_id
* description/particulars
* amount
* currency
* paid_at
* paid_to
* reference/receipt number nullable
* notes nullable
* status if appropriate
* created_by
* updated_by
* created_at
* updated_at

IMPORTANT:

router_id MUST be nullable.

Some expenses belong to a specific router:

Example:
"Bought 50GB internet bundle for Router #3"

Other expenses may belong to the entire business:

Example:
"Office electricity bill"

Therefore:

router_id = null

must be supported.

==================================================
5. PARTICULARS / DESCRIPTION
============================

The user must be able to enter a meaningful description of what they paid for.

Examples:

"Monthly internet bundle for Router #003"

"Bought TP-Link access point for new customer site"

"Electricity bill for Mbezi site - September"

"Technician payment for Router #12 repair"

Do not make the expense type itself the description.

The expense type tells us WHAT CATEGORY it belongs to.

The particulars/description tells us exactly WHAT was purchased or paid for.

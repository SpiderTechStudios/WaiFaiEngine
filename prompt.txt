The /login endpoint must:

2. Resolve the gateway using the existing GatewayResolver.
3. Resolve or create the appropriate captive session using the existing production service where appropriate.
4. Store the original destination URL.
5. Store client IP/MAC and gateway information.
6. Prepare the authentication portal.
7. Redirect/render the actual production portal.

CRITICAL:

6. TOKEN GENERATION HAPPENS AFTER SUCCESSFUL AUTHENTICATION
===========================================================

After the user has successfully authenticated through the production portal:

1. Confirm the user/device is authorized.
2. Generate or obtain the WiFiDog authentication token.
3. Persist the token/session association using the existing production captive-session mechanism.
4. Associate the token with:

   * gateway
   * client IP
   * client MAC
   * authenticated user/session
5. Record token creation time and expiration if the existing data model supports it.

The token must NOT be created merely because /login was called.

The token represents the successful authentication that the gateway will verify.

8. /auth IS THE SERVER-TO-SERVER CALLBACK
=========================================

Implement:

GET/POST /api/wifidog/auth

This endpoint is NOT the user-facing portal.

The RAP62-OD should call this endpoint server-to-server after receiving:

/wifidog/auth?token=...

The request will contain parameters such as:

stage=login
gw_id
gw_sn
ip
mac
token
incoming
outgoing

Log the complete request safely for diagnostics.

DO NOT log the raw authentication token in production logs.

Use a SHA-256 hash of the token when logging.

==================================================
9. /auth stage=login
====================

When:

stage=login

the server must:

1. Validate the gateway.
2. Validate the token.
3. Confirm that the token exists.
4. Confirm the token belongs to the expected gateway/client where applicable.
5. Confirm the token/session has not expired.
6. Confirm the underlying user/device is still authorized.
7. Mark the captive session as authenticated/authorized.
8. Store gateway/client authentication state.
9. Record the authentication timestamp.
10. Return EXACTLY:

Auth:1

for successful authorization.

Response must be plain text.

Do not return JSON.

Do not return:

{
"auth": true
}

Do not return:

Auth: 1

Use exactly:

Auth:1

with HTTP 200.

For failure return:

Auth:0

also as plain text.

==================================================
10. DO NOT CONFUSE /auth WITH /portal
=====================================

This is critical.

/api/wifidog/auth

is the authorization callback.

It returns:

Auth:1

or:

Auth:0

/api/wifidog/portal

is the user-facing/result page.

It MUST NOT return Auth:1.

It must render/display the result of the WiFiDog authentication.

If the gateway redirects to:

/api/wifidog/portal?message=denied

show an authentication failure page.

If authentication succeeded, show the success page or redirect to the saved original URL.
